- `Any` is a universal wildcard type: any non-nil value/type is `==`/`===` to it and back, no composition required.
- `Table`'s CRUD methods return a real, model-shaped `Struct` instead of a `Dictionary` when the model has a structured `Table` reference (`Tasks | Table<'tasks', Task> {}`); falls back to `Dictionary` otherwise. `create` also now returns the created record itself, not just the id (docs/tests updated to match).

Chain-aware variant matching (`tag_chains_equal?`/`tag_chains_satisfy?`) so `Ab\Cd`/`Ab\Ce` are distinct. Runtime `x.tag = new_tag` allowed only on a value whose type was declared with a tag, and only when `new_tag =>=` the current tag at every chain link (`Prog::Tag_Signature_Violation` otherwise).

- Where internal/reflective keys should live. Things like a Struct's own `.name`/`.names`/`.type_names`/`.types`/`.values`/`.members`, and a Type/Instance's `.name`/`.display_name`/`.types`, sit in the exact same declarations namespace as user-declared members -- so a schema member that happens to share one of those names (`Property <name: String>`, `Layer_Order <names: Array\String>`) gets silently clobbered by the reflective value instead of holding its own real data. Found and patched three instances of this same collision class in one sitting (`interp_struct_call`'s `.name` backfill, `build_struct`'s `.names`/`.type_names`/`.types`/`.values`/`.members` backfill, and `run_type_body_on_instance` re-running `backend/struct.prog`'s own body over top of a struct instance) -- there may well be more, and patching each collision site one at a time as it's discovered isn't a real fix, just whack-a-mole. Fourth instance found (2026-09-04), not yet patched: `expressions.prog`'s own `Structure` type needs a member literally named `types` (and `names`) -- `Structure | Expression <types: Array\Any, names: Array\String, declared_name: String>` -- which collides with `build_struct`'s reflective bookkeeping the same way; concretely, `interp_struct_composition`'s `own.type_objects[i]` (interpreter.rb:3106) comes back `nil` and crashes, because `build_struct`'s final re-assert-real-members pass (interpreter.rb:3715-3718) overwrites `@declarations['types']` with the `types` member's own per-instance value instead of leaving the reflective type-objects array in place. Repro: `Abc <abc: Int>` / `Both2 | Abc <types: String, my_own: String>` / `Both2(1, 'x', 'yo')`. Leaving unfixed until the `@.` redesign below actually happens, rather than patching a fourth whack-a-mole site. Original vision for the language was for all internal keys to be reached through a distinct `@.` namespace (`@.name`, `@.types`, ...) instead of sharing plain dot-access with user declarations -- revisit whether that (or some other real separation) is worth doing now, rather than continuing to patch collisions as they surface. **RESOLVED (2026-09-05) via the `@ : Identity{}` redesign below (stage 4).** All of `name`/`display_name`/`types`/`composed_types`/`type_names`/`type_objects`/`names`/`values`/`members`/`static_declarations` and the Enum quartet are now `@`-only, off `@declarations`. The `Structure <types: Array\Any, names: Array\String>` repro works. The re-assert pass and reflective backfills in `build_struct` are gone.
- Scope-lookup coherence pass: `@splat` (writable) / `@splatr` (read-only) / `@unsplat` replace the 11 old `@add_*`/`@remove_*`/`@readable`/`@writable`/`@splatw` names; `@push_scope`/`@pop_scope` kept as the distinct "reopen" verb. `~/` is now a bare `Global` scope keyword (like `self`/`Self` -- a value on its own, `Global.x` is plain dot access); `SCOPE_OPERATORS` gone, `SCOPE_KEYWORDS = %w(self Self Global)`. `examples/scopes.prog` rewritten, CLAUDE.md/readme.md updated.
- `Prog::Context::MEMBERS` (context.rb) is the single source of truth for every `@` member; `Context::FUNCTIONS`/`STACK_FUNCTIONS`/`VITALS` derive from it, `constants.rb` holds none of them, `SCOPE_FUNCTION_ALIASES` deleted. `test/context_test.rb` locks `backend/context.prog`'s member list to `MEMBERS.keys`.
- `Ident[...]` only parses as an Enum declaration when `Ident` is undeclared -- the parser tracks `:=`/`=`/`x,`/param/`x: Type` names as it goes. Fixes an already-declared `INPUT` being misread as an enum in `INPUT[0...2]`.
- `a.b...c` parses as `(a.b)...c`, not `a.(b...c)` -- a `.`/`.?` RHS no longer absorbs a trailing range operator (the RANGE branch in `complete_expression` was missing the precedence guard its siblings have).
- `Prog::Struct#[]=` keeps the positional `@values` snapshot and each `@.members` Member in step with `@declarations`, so a struct mutated after construction prints/iterates/`to_h`s its current values. `@.values`/`@.members` on a struct read straight off it, not the first-`@`-access Context snapshot.
- Type aliases resolve in contract checks: `-> Int` returning an `Integer`, `x: Int = 4`, `x: Dec = Decimal(...)` all pass. Runtime `type_contract_satisfied?` resolves an alias to its real type's composed set; the static checker gets a small `TYPE_ALIASES` map.
- A `@splat`/`@splatr` param's `: Type` / `: <...>` annotation is enforced at the call (`check_splat_param_type_contract`) -- wrong shape raises `Type_Contract_Violation` there, not an `Undeclared_Identifier` deep in the body. `Type_Contract_Violation` now carries a source location.
- `bin/drive` self-heals the Ruby version -- run through the `/usr/local/bin/drive` symlink from any directory and it re-execs under `.ruby-version` if the shim picked a different one.
